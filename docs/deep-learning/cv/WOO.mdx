# Watch Only Once (WOO)

**Paper:** Shoufa Chen et al., Watch Only Once: An End-to-End Video Action Detection Framework, ICCV 2021.

**Paper link:** https://openaccess.thecvf.com/content/ICCV2021/papers/Chen_Watch_Only_Once_An_End-to-End_Video_Action_Detection_Framework_ICCV_2021_paper.pdf

**Code:** https://github.com/ShoufaChen/WOO

![WOO unified pipeline: one backbone produces both boxes and action labels](https://raw.githubusercontent.com/SAILTECHTEAM/knowledge-base/main/static/img/cv_img/WOOimg/image1.png)

## Core Idea of WOO

WOO watches a video clip once with a single network and outputs actor bounding boxes together with action categories. No separate person detector and no post-processing such as non-maximum suppression are required at test time.

## Problem Background

### Abstract

> *We propose an end-to-end pipeline named Watch Only Once (WOO) for video action detection. Current methods either split video action detection into independent stages for actor localization and action classification, or train two independent models within one stage. In contrast, our method solves actor localization and action classification simultaneously in a unified network. By unifying the backbone network and removing many manually designed components, the whole pipeline is significantly simplified. WOO uses a unified video backbone to extract features for actor localization and action classification at the same time. In addition, we introduce spatiotemporal action embeddings into the framework and design a spatiotemporal fusion module to obtain richer and more discriminative features, further improving action classification performance. Extensive experiments on the AVA and JHMDB datasets show that WOO achieves state-of-the-art performance while reducing GFLOPs by up to 16.7% compared with existing methods.*

- **FLOPs** count the floating-point operations of one forward pass.
- **GFLOPs** equal $10^9$ FLOPs. Higher values mean heavier computation and slower inference.

### Video Detection Contains Two Subtasks

Video action detection asks where each person is and what each person is doing. A single frame is usually enough for locating people, while judging actions needs motion across multiple frames. This mismatch is the central difficulty.

### Traditional Methods Compared in the Paper

![Two-backbone action detection pipeline versus the unified WOO pipeline](https://raw.githubusercontent.com/SAILTECHTEAM/knowledge-base/main/static/img/cv_img/WOOimg/image2.png)

YOWO belongs to the one-training-stage but two-backbone family. It still runs a 2D CNN for detection and a 3D CNN for action modeling, so features are extracted from raw pixels twice. WOO argues that this design is effectively still two models and aims to complete both tasks with one backbone and one forward pass.

### The Innovation of WOO

WOO uses a single video backbone for both heads. The same clip is watched once, and the network produces localization and classification outputs together.

## WOO Structure

:::info[Three components]
WOO consists of a unified backbone network, spatiotemporal action embeddings, and a spatiotemporal fusion module inside the classification head.
:::

### Unified Backbone Network

A single backbone carries temporal and spatial information at the same time. The key design is to separate key-frame features early so detection keeps clean spatial detail while classification keeps full temporal context.

![Separate 2D plus 3D backbones versus the unified backbone with early key-frame separation](https://raw.githubusercontent.com/SAILTECHTEAM/knowledge-base/main/static/img/cv_img/WOOimg/image3.png)

In the traditional separate design, a 2D detector handles the key frame and a 3D network handles the clip. The 3D branch often uses dilated convolution in its last stage (called DC5) to keep spatial resolution while enlarging the receptive field. WOO removes this dilation because dilation alone does not solve a deeper problem: as the network deepens, temporal convolutions keep mixing neighboring frames into the key frame, so the spatial detail needed for detection gets blurred.

WOO therefore separates the key frame early. Formally, let

$$X \in \mathbb{R}^{C \times T \times H \times W}$$

denote the spatiotemporal feature map of a layer, where $C$ is the channel count and $T$ is time. The key frame sits in the middle of the clip. Let

$$X_t = X[T/2] \in \mathbb{R}^{C \times H \times W}$$

denote the key-frame feature map.

A lightweight feature pyramid network takes key-frame features from early stages (res2 through res5) and builds multi-scale spatial features for the localization head. The full clip features continue to the last stage for the classification head. Detection thus replaces a separate 2D backbone with a small pyramid, which is where the parameter and FLOP savings come from.

### Spatiotemporal Action Embedding

Action classification is harder than localization, and the authors observe that the unified network localizes well but classifies less well. Their stated hypothesis is that one backbone serving both tasks leans toward localization. To strengthen classification, they add a dedicated branch with spatial and temporal action embeddings and an interaction step between actors.

> Original paper: "We found that the unified architecture performs well for localization, but action classification is still limited. Therefore, we suspect that when the same backbone serves both tasks, it will be biased toward the localization task, affecting action classification performance."

### Spatiotemporal Fusion Module

The fusion module sits inside the classification head. It combines spatial cues such as shape and pose with temporal cues such as motion and duration, and produces the final features used for classification.

### Actor Localization Head

- This head follows Sparse R-CNN, an end-to-end detector without hand-crafted anchors or test-time suppression.
- The input is the multi-scale key-frame pyramid. The output is a fixed set of boxes with confidence scores.
- Training uses set prediction loss with bipartite matching, so each ground-truth person is matched to exactly one predicted box. At test time the predicted set is used directly.
- Because detection and classification share the backbone, no separate detector pretraining is needed.

Set prediction means the model always predicts a fixed number of boxes and the matcher assigns each ground-truth box its best partner:

```text
Ground truth: 3 people
Model output: for example 100 boxes
Matching: each of the 3 people receives exactly one box,
  remaining boxes are treated as background.
```

### Action Classification Head

![RoIAlign splitting of actor features into spatial and temporal branches](https://raw.githubusercontent.com/SAILTECHTEAM/knowledge-base/main/static/img/cv_img/WOOimg/image7.png)

For each detected person, RoIAlign crops the person's region from the last-stage clip features and normalizes it to a fixed spatial size. The cropped volume is then split:

```text
Detected person -> RoIAlign crop ->
  spatial branch (pool over time, keep layout) and
  temporal branch (pool over space, keep motion) ->
  actor interaction -> fusion -> classification
```

The temporal branch pools over spatial dimensions and keeps change over time. The spatial branch pools over time and keeps structure. Direct concatenation of the two is kept as a baseline, and the embedding interaction described next is added to sharpen the features.

![Actor-to-actor interaction between spatial and temporal embeddings](https://raw.githubusercontent.com/SAILTECHTEAM/knowledge-base/main/static/img/cv_img/WOOimg/image9.png)

People in the same clip often interact, so the current person's features alone can be ambiguous. The interaction module therefore models relations between actors. For $N$ detected actors, the paper defines spatial and temporal embeddings $E_s \in \mathbb{R}^{N \times d}$ and $E_t \in \mathbb{R}^{N \times d}$, obtains queries, keys, and values through linear layers, and computes attention scores between actors. Scores are scaled by $\frac{QK^{T}}{\sqrt{d}}$ before softmax so large dimensions do not saturate the gradients. The attended embeddings are projected back with $1 \times 1$ convolutions and fused into the actor features.

### Embedding

To save computation, attention runs between lightweight per-actor embeddings rather than full feature maps.

> Original text: "The embedding is lighter compared to the feature map, we adopt the attention mechanism between embedding instead of feature maps for efficiency."

In other words, relation modeling stays in the compact embedding space, and only the resulting relation signal is written back into the high-dimensional features.

:::caution[What the paper leaves unspecified]
The paper states that each of the $N$ actor features has its own embedding but does not show the exact initialization of these embeddings. The description above follows the paper's equations and text. Details beyond that are interpretation, not quoted method.
:::

### A Short Note on Attention

Attention helps the model decide what to emphasize. Higher weights mean larger influence on the output.

Channel attention of the CBAM type asks which channels and regions matter inside one feature map, without distinguishing people. Actor-to-actor attention of the WOO type asks how much each person should refer to other people. The WOO interaction module belongs to the second kind: it is transformer-style attention over actors, comparable in form to self-attention over tokens.

![Comparison of channel attention with actor-to-actor attention](https://raw.githubusercontent.com/SAILTECHTEAM/knowledge-base/main/static/img/cv_img/WOOimg/image10.png)
