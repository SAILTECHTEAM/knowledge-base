# Temporal Shift Module (TSM)

**Paper:** Ji Lin, Chuang Gan, Song Han, TSM: Temporal Shift Module for Efficient Video Understanding, ICCV 2019.

**Paper link:** https://openaccess.thecvf.com/content_ICCV_2019/papers/Lin_TSM_Temporal_Shift_Module_for_Efficient_Video_Understanding_ICCV_2019_paper.pdf

**Code:** https://github.com/mit-han-lab/temporal-shift-module

![TSM overview: shift part of the channels in time, then apply 2D convolution](https://raw.githubusercontent.com/SAILTECHTEAM/knowledge-base/main/static/img/cv_img/TSMimg/image1.png)

Compared with 2D CNNs, which extract spatial features from one frame at a time, 3D CNNs model space and time together and capture richer spatiotemporal structure.

**3D convolution**

![3D convolution over space and time](https://raw.githubusercontent.com/SAILTECHTEAM/knowledge-base/main/static/img/cv_img/TSMimg/image2.png)

**2D convolution**

![2D convolution over a single frame](https://raw.githubusercontent.com/SAILTECHTEAM/knowledge-base/main/static/img/cv_img/TSMimg/image3.png)

3D convolution adds computation along the temporal dimension, which raises cost and parameter count and makes deployment difficult in real-time or resource-limited settings. The central question is therefore:

> Can temporal modeling be added while keeping the efficiency of 2D CNNs?

## Solution

### TSM Shifts Part of the Channels in Time

The feature has four dimensions, where $C$ is the channel dimension and $T$ is the temporal dimension.

![Channel shift along the temporal dimension](https://raw.githubusercontent.com/SAILTECHTEAM/knowledge-base/main/static/img/cv_img/TSMimg/image4.png)

The core operation shifts a fraction of the channels forward and backward along time. After the shift, each frame carries some channels from its neighbors, so a plain 2D convolution applied afterwards mixes temporal information while the computation itself stays two-dimensional.

### The Role of the Shift

![Offline bidirectional shift versus online unidirectional shift](https://raw.githubusercontent.com/SAILTECHTEAM/knowledge-base/main/static/img/cv_img/TSMimg/image5.png)

Taking panel (b) as an example, the current frame gathers shifted channels from frame $t-1$ and frame $t+1$. The paper shifts by one frame in each direction.

- Panel (b), offline shift, is bidirectional. The current frame can use past and future information because the whole video is already available.
- Panel (c), online shift, is unidirectional. Future frames do not exist yet, so channels move only from the past to the present. The operation changes only data addresses, so it adds no FLOPs and no parameters.

### Core Idea

Shift first, then convolve. After the shift, the 2D convolution fuses the mixed channels. Which channels matter most in time is left for the network to learn, since the answer varies across layers and tasks.

Batch-parallel processing along time becomes possible because the heavy operation remains 2D convolution. The shift supplies the temporal mixing, and the following convolution performs the fusion.

## Shift Proportion and Placement

![Latency overhead and accuracy for different shift proportions](https://raw.githubusercontent.com/SAILTECHTEAM/knowledge-base/main/static/img/cv_img/TSMimg/image6.png)

Panel (a) reports latency overhead from data movement. Shifting all channels adds up to about 13.7 percent overhead on CPU, which is not negligible. Shifting a small fraction such as 1/8 limits the overhead to around 3 percent. The paper therefore shifts only part of the channels.

Panel (b) compares accuracy. Residual shift consistently outperforms in-place shift. Accuracy first rises with more shifted channels because temporal reasoning improves, then falls because spatial modeling of the current frame suffers. The peak for residual shift is at one quarter of the channels.

:::tip[Default setting]
The paper uses residual shift of 1/4 of the channels as the default: 1/8 forward and 1/8 backward for offline bidirectional modeling.
:::

### Model Design: Residual TSM and In-Place TSM

![In-place shift before the residual block versus shift inside the residual branch](https://raw.githubusercontent.com/SAILTECHTEAM/knowledge-base/main/static/img/cv_img/TSMimg/image7.png)

In-place shift inserts the operation before a convolution layer or residual block. Shifted channels leave the current frame, so the current frame loses the information those channels carried. When many channels move, the backbone's ability to represent the present image degrades.

Residual shift places the operation inside the residual branch. The identity path still carries the complete current-frame activation, so temporal information is added without removing the original content. Even when all branch channels shift, the shortcut preserves spatial capacity, which is why residual shift beats in-place shift at every proportion in the paper's Kinetics comparison.

## Offline TSM Video Models

![Offline TSM video model with bidirectional temporal exchange](https://raw.githubusercontent.com/SAILTECHTEAM/knowledge-base/main/static/img/cv_img/TSMimg/image8.png)

Offline inference sees the whole recorded video, so future frames are available. The model shifts part of the channels forward and part backward, which implements bidirectional exchange across time. Video sampling produces frames, an early ordinary ResNet convolution extracts spatial structure, and later 2D convolutions fuse the shifted mixture. Since the shift itself has no parameters, all learning happens in the convolutions that follow it.

## Online Temporal Shift

Online inference cannot use future frames, so the shift is unidirectional.

![Unidirectional TSM pipeline for online recognition with a feature cache](https://raw.githubusercontent.com/SAILTECHTEAM/knowledge-base/main/static/img/cv_img/TSMimg/image9.png)

![Detail of the online shift: cached past channels replace part of the current frame](https://raw.githubusercontent.com/SAILTECHTEAM/knowledge-base/main/static/img/cv_img/TSMimg/image10.png)

For each frame and each residual block, the first 1/8 of the feature maps are saved in memory. When the next frame arrives, its first 1/8 is replaced by the cached maps. The layer therefore processes 7/8 of the present frame together with 1/8 from the past. This design has three practical effects:

- Low-latency inference: each frame needs only a small replace-and-cache step, so per-frame latency stays close to the 2D baseline.
- Low memory usage: only a small fraction of features is cached (the paper reports about 0.9 MB extra for ResNet-50).
- Multi-level temporal fusion: the same operation repeats at every stage, so temporal mixing happens throughout the network.

The 1/8 figure follows directly from the offline result. Offline bidirectional shift uses 1/4 in total:

```text
Offline bidirectional TSM: 1/4 total = 1/8 forward + 1/8 backward
Online unidirectional TSM: 1/8 total = past frames only
```
