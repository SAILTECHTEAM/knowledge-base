# Logging and Metrics

Lightning provides a unified logging interface through `self.log()` that integrates with multiple backends. Metrics are tracked per step and aggregated per epoch automatically.

## The self.log Method

```python
class MyModel(L.LightningModule):
    def training_step(self, batch, batch_idx):
        x, y = batch
        loss = self(x, y)
        
        # Basic logging
        self.log("train_loss", loss)
        
        return loss
```

### Logging Parameters

```python
def training_step(self, batch, batch_idx):
    x, y = batch
    loss = self(x, y)
    
    self.log(
        name="train_loss",     # Metric name
        value=loss,          # Metric value
        on_step=False,      # Log at every step
        on_epoch=True,     # Aggregate at epoch end
        prog_bar=False,    # Show on progress bar
        logger=True,      # Log to logger
        reduce_fgtx=True  # Reduce across epochs (default: mean)
    )
```

| Parameter | Description | Common Values |
| :--- | :--- | :--- |
| `name` | Metric name | `"train_loss"`, `"val_acc"` |
| `value` | Metric value | Float tensor or number |
| `on_step` | Log every batch | `True`/`False` |
| `on_epoch` | Aggregate at epoch end | `True` (default) |
| `prog_bar` | Show on progress bar | `True`/`False` |
| `logger` | Log to logger | `True` (default) |
| `reduce_fgtx` | Reduce across devices | `True` (default: mean) |

### Step vs Epoch Logging

```python
def training_step(self, batch, batch_idx):
    loss = self.compute_loss(batch)
    
    # Log every step (verbose, good for debugging)
    self.log("train_loss_step", loss, on_step=True, on_epoch=False)
    
    # Log epoch-level (aggregated automatically)
    self.log("train_loss", loss, on_step=False, on_epoch=True)
    
    return loss
```

| Configuration | Behavior |
| :--- | --- |
| `on_step=True, on_epoch=False` | Logs every batch |
| `on_step=False, on_epoch=True` | Logs epoch average |
| `on_step=True, on_epoch=True` | Logs both step and epoch |

:::tip[Progress Bar]
Use `prog_bar=True` for key metrics to monitor training visually. Avoid overusing — too many metrics slow down the progress bar.
:::

## log_dict

Log multiple metrics at once:

```python
def validation_step(self, batch, batch_idx):
    x, y = batch
    preds = self(x)
    loss = F.cross_entropy(preds, y)
    
    preds_idx = torch.argmax(preds, dim=1)
    acc = (preds_idx == y).float().mean()
    
    # Multiple metrics
    self.log_dict({
        "val_loss": loss,
        "val_acc": acc,
    }, on_step=False, on_epoch=True)
    
    return loss
```

## Metrics Integration

### Using TorchMetrics

Lightning integrates with `torchmetrics` for standardized metrics:

```python
import torchmetrics

class MyModel(L.LightningModule):
    def __init__(self):
        super().__init__()
        self.accuracy = torchmetrics.Accuracy(task="multiclass", num_classes=10)
        self.f1 = torchmetrics.F1Score(task="multiclass", num_classes=10)
    
    def validation_step(self, batch, batch_idx):
        x, y = batch
        preds = self.model(x)
        
        # Update metrics directly
        self.accuracy(preds, y)
        self.f1(preds, y)
        
        # Log the metric objects directly
        self.log("val_acc", self.accuracy, on_epoch=True)
        self.log("val_f1", self.f1, on_epoch=True)
        
        return F.cross_entropy(preds, y)
```

:::tip[Automatic Metric Computation and Reset]
When you log a `torchmetrics.Metric` object directly using `self.log()`, Lightning automatically handles calling `.compute()` at the end of the epoch and `.reset()` at the start of the next epoch. You don't need to implement `on_validation_epoch_end` manually for this.
:::

## Common Logging Patterns

### Logging Loss Only

```python
def training_step(self, batch, batch_idx):
    loss = self.compute_loss(batch)
    
    self.log("train_loss", loss, on_step=True, on_epoch=True, prog_bar=True)
    
    return loss
```

### Logging Loss and Accuracy

```python
def validation_step(self, batch, batch_idx):
    x, y = batch
    preds = self(x)
    
    loss = F.cross_entropy(preds, y)
    preds_class = torch.argmax(preds, dim=1)
    acc = (preds_class == y).float().mean()
    
    self.log_dict({
        "val_loss": loss,
        "val_acc": acc,
    }, on_step=False, on_epoch=True, prog_bar=True)
    
    return loss
```

### Logging Custom Metrics

```python
def training_step(self, batch, batch_idx):
    x, y = batch
    output = self(x)
    
    # Custom metric: mean prediction confidence
    probs = F.softmax(output, dim=1)
    confidence = probs.max(dim=1)[0].mean()
    
    self.log("train_confidence", confidence, on_step=True)
    
    return F.cross_entropy(output, y)
```

## Example: Complete Logging Setup

```python
import lightning as L
import torch
import torchmetrics
import torch.nn.functional as F

class LitModel(L.LightningModule):
    def __init__(self, num_classes=10):
        super().__init__()
        self.model = torch.nn.Linear(784, num_classes)
        self.accuracy = torchmetrics.Accuracy(task="multiclass", num_classes=num_classes)
    
    def forward(self, x):
        return self.model(x.view(x.size(0), -1))
    
    def configure_optimizers(self):
        return torch.optim.Adam(self.parameters(), lr=1e-3)
    
    def training_step(self, batch, batch_idx):
        x, y = batch
        logits = self(x)
        loss = F.cross_entropy(logits, y)
        
        self.log(
            "train_loss", loss,
            on_step=True, on_epoch=True,
            prog_bar=True, logger=True
        )
        
        return loss
    
    def validation_step(self, batch, batch_idx):
        x, y = batch
        logits = self(x)
        loss = F.cross_entropy(logits, y)
        
        self.accuracy(logits, y)
        
        self.log_dict({
            "val_loss": loss,
            "val_acc": self.accuracy,
        }, on_step=False, on_epoch=True, prog_bar=True)
        
        return loss
```

## Comparison: Logging in Raw PyTorch

| Aspect | Raw PyTorch | Lightning |
| :--- | :--- | :--- |
| Logging | Manual per step | `self.log()` |
| Aggregation | Manual average | Automatic |
| Multiple Loggers | Multiple libraries | `logger=[...]` |
| Progress Bar | `tqdm` manual | `prog_bar=True` |
| Metric Reset | Manual | `on_epoch_end` or automatic |

:::tip[Consistent Logging]
Use `self.log()` throughout. Avoid mixing manual logging — it breaks integration with checkpointing callbacks that monitor metrics.
:::
