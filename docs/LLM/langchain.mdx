# LangChain Framework

LangChain is a toolkit for building LLM-powered applications. It handles prompts, memory, document search (RAG), tool calling, and multi‑agent workflows – integrated with `uv` for fast, reproducible Python environments.

---

## Prerequisites

- Python 3.11+
- `uv` ([install](https://docs.astral.sh/uv/))
- OpenAI API key (or other LLM provider)

---

## Core Architecture

| Layer | Domain | Responsibility | Key Components |
|-------|--------|----------------|----------------|
| Orchestration | `LangGraph` | Stateful multi‑agent graphs, loops, human‑in‑the‑loop | `StateGraph`, `MessagesState` |
| Interface Base | `langchain-core` | Execution primitives, LCEL pipe protocol | `Runnable`, `ChatPromptTemplate` |
| Integrations | `langchain-community` | Third‑party models, vector stores, loaders | `Chroma`, `ChatOpenAI`, `PyPDFLoader` |
| Observability | `LangSmith` | Tracing, cost monitoring, evaluation | Automated trace injection |

### Component Roles

| Component | Language | Purpose |
|-----------|----------|---------|
| LCEL Engine | Python/Rust | Unified streaming, batch, async |
| Model I/O | Python | Prompts, configs, token schemas |
| Data Retrieval | Python | Document loading, splitting, embedding |
| Tool Execution | Python | Function‑calling with validation |

## LCEL – LangChain Expression Language

LCEL chains components with the pipe operator `|`.  
Flow: `Input → Prompt → Model → Parser → Output`

### Runnable Methods

| Method | Async | Behaviour |
|--------|-------|-----------|
| `invoke(input)` | `ainvoke` | Single call, full result |
| `stream(input)` | `astream` | Yields tokens as they arrive |
| `batch([inputs])` | `abatch` | Parallel processing |

### Basic Chain

```python
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_openai import ChatOpenAI

prompt = ChatPromptTemplate.from_messages([
    ("system", "Answer: {question}")
])
model = ChatOpenAI(model="gpt-4o-mini", temperature=0)
parser = StrOutputParser()

chain = prompt | model | parser
answer = chain.invoke({"question": "What is RAG?"})
```

### Flow Helpers

| Helper | Purpose |
|--------|---------|
| `RunnablePassthrough()` | Pass input unchanged |
| `RunnableLambda(func)` | Wrap any Python function |
| `RunnableParallel(...)` | Execute sub‑chains concurrently |

```python
from langchain_core.runnables import RunnablePassthrough, RunnableParallel

pipeline = RunnableParallel(
    raw=RunnablePassthrough(),
    upper=lambda x: x["text"].upper()
)
```

## RAG – Retrieval-Augmented Generation

RAG answers questions from private documents.  
Pipeline: `Load → Split → Embed → Store → Retrieve → Generate`

### Types of RAG

| Type | Description | When to use |
|------|-------------|--------------|
| **Normal RAG** | Vector similarity search on document chunks. | General Q&A on static documents. |
| **Graph RAG** | Uses a knowledge graph (entities, relationships). | Structured data (e.g., legal texts, wikis). |
| **Agentic RAG** | Agent decides *how* to retrieve (multiple retrievers, query rewriting, web search). | Complex queries requiring reasoning or fallback. |

### Implementation Steps (Normal RAG)

**1. Load documents**

```python
from langchain_community.document_loaders import TextLoader
loader = TextLoader("data/doc.txt")
docs = loader.load()
```

**2. Split into chunks**

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter
splitter = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=50)
chunks = splitter.split_documents(docs)
```

**3. Embed and store**

```python
from langchain_openai import OpenAIEmbeddings
from langchain_chroma import Chroma
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vectorstore = Chroma.from_documents(chunks, embeddings, persist_directory="./chroma_db")
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})
```

**4. Build RAG chain**

```python
from langchain_core.runnables import RunnablePassthrough

def format_docs(docs):
    return "\n\n".join(d.page_content for d in docs)

rag_prompt = ChatPromptTemplate.from_template("""
Context: {context}
Question: {question}
Answer:
""")

rag_chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | rag_prompt
    | model
    | StrOutputParser()
)

answer = rag_chain.invoke("What is the loan period?")
```

### Tuning Guide

| Parameter | Recommended | Trade‑off |
|-----------|-------------|------------|
| `chunk_size` | 400–800 tokens | Larger = more context but more noise |
| `chunk_overlap` | 10–20% of size | Prevents broken sentences |
| `k` | 3–5 | More chunks = more variety, risk of distraction |

## Memory & State Management

Memory preserves conversation history across turns. Without memory, LLM APIs are stateless.

### Key Advantages of LangChain Memory

- **Automated Context Management** – LangChain automatically formats and injects history into prompts; no manual concatenation.
- **Token Optimization** – Use `ConversationSummaryMemory` or `ConversationBufferWindowMemory` to trim/compress history, saving costs.
- **Persistent State Storage** – Attach memory to external databases (Redis, PostgreSQL, vector DBs) for cross‑session recall.
- **Entity Extraction** – Extract and remember specific facts (e.g., “User’s name is Alice”) instead of raw logs.

### Comparison with Direct API Usage

| Aspect | Direct LLM API | LangChain with Memory |
|--------|----------------|----------------------|
| State management | Manual history concatenation | Automatic injection |
| Token usage | Full history every time | Window/summary compression |
| Session handling | Custom implementation | Built‑in `RunnableWithMessageHistory` |
| Persistence | None | Pluggable (Redis, DB, etc.) |

### Example (Buffer Memory)

```python
from langchain_core.chat_history import InMemoryChatMessageHistory
from langchain_core.runnables.history import RunnableWithMessageHistory

store = {}

def get_session_history(session_id):
    if session_id not in store:
        store[session_id] = InMemoryChatMessageHistory()
    return store[session_id]

prompt = ChatPromptTemplate.from_messages([
    ("system", "You are an assistant. History: {history}"),
    ("human", "{input}")
])

chain = prompt | model | parser
chain_with_memory = RunnableWithMessageHistory(
    chain, get_session_history,
    input_messages_key="input",
    history_messages_key="history"
)

response = chain_with_memory.invoke(
    {"input": "My name is Alice"},
    config={"configurable": {"session_id": "user123"}}
)
```

## Tools & Agents

Tools are functions an LLM can call. Agents decide when and how to call them.

### Define a Tool

```python
from langchain_core.tools import tool

@tool
def search_catalog(title: str) -> str:
    """Search for a book by title."""
    return f"{title} found on shelf A12."
```

### Create an Agent

```python
from langgraph.prebuilt import create_react_agent

agent = create_react_agent(
    model=model,
    tools=[search_catalog],
    state_modifier="You are a library assistant. Use the search tool when needed."
)

result = agent.invoke({"messages": [("user", "Where is Dune?")]})
print(result["messages"][-1].content)
```

**Agent cycle:** Reason → Act → Observe → Answer (repeat if needed).

## LangGraph – Complex Workflows

LangGraph handles loops, conditionals, and multi‑agent coordination.

### Simple State Graph

```python
from langgraph.graph import StateGraph, END
from typing import TypedDict

class State(TypedDict):
    question: str
    answer: str

def route(state):
    if "book" in state["question"].lower():
        return {"answer": "I can help with books."}
    return {"answer": "I only answer book questions."}

graph = StateGraph(State)
graph.add_node("router", route)
graph.set_entry_point("router")
graph.add_edge("router", END)
app = graph.compile()
```

### Supervisor‑Workers (Multi‑Agent)

```python
from langgraph_supervisor import create_supervisor
from langgraph.prebuilt import create_react_agent

book_agent = create_react_agent(model, [search_catalog], name="book_helper")
hours_agent = create_react_agent(model, [], name="hours_helper")

supervisor = create_supervisor(
    agents=[book_agent, hours_agent],
    model=model,
    prompt="Route book questions to book_helper, hours to hours_helper."
)
```

## Best Practices & Pitfalls

### Safety Rules

1. `temperature=0` for tool calling and routing.
2. Set `recursion_limit=10` to prevent infinite loops.
3. Never use f‑strings to build prompts from user input (risk of injection).
4. Always bound `k` in retrievers: `search_kwargs={"k": 3}`.

### Common Issues

| Problem | Cause | Fix |
|---------|-------|-----|
| `invoke` returns `AIMessage` | Missing output parser | Add `\| StrOutputParser()` |
| Memory not working | No `{history}` in prompt | Include `{history}` placeholder |
| Agent loops forever | No iteration limit | Set `recursion_limit` |
| High token usage | `chunk_size` too large | Reduce to 400–600 |

### Production Quality Gates

```python
llm = ChatOpenAI(model="gpt-4o", temperature=0, max_retries=2, timeout=15)
chain.batch(inputs, config={"max_concurrency": 5})
```

## Serving LangChain as an API Endpoint

**LangChain outputs can be served as REST API endpoints.** Wrap any chain/agent in FastAPI.

### Output Formats

| Output type | Method | Use case |
|-------------|--------|----------|
| Plain text | `StrOutputParser()` | Simple Q&A |
| JSON | `JsonOutputParser()` | Structured data |
| Streamed chunks | `.stream()` + `StreamingResponse` | Real‑time UI |
| Raw documents | `retriever.invoke()` | Search endpoint |

### Example: FastAPI RAG Endpoint

```python
from fastapi import FastAPI, Query
from langchain_community.document_loaders import TextLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain_chroma import Chroma
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import RunnablePassthrough
from langchain_core.output_parsers import StrOutputParser

loader = TextLoader("langchain_guide.md")
docs = loader.load()
splitter = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=50)
chunks = splitter.split_documents(docs)

embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vectorstore = Chroma.from_documents(chunks, embeddings)
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})

def format_docs(docs):
    return "\n\n".join(d.page_content for d in docs)

prompt = ChatPromptTemplate.from_template("""
Context: {context}
Question: {question}
Answer:
""")
model = ChatOpenAI(model="gpt-4o-mini", temperature=0)
rag_chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | prompt
    | model
    | StrOutputParser()
)

app = FastAPI()

@app.get("/ask")
async def ask(question: str = Query(...)):
    return {"answer": rag_chain.invoke(question)}
```

Run: `uv run uvicorn api:app --reload --port 8000`  
Test: `curl "http://localhost:8000/ask?question=What%20is%20LCEL?"`

### Streaming Endpoint

```python
from fastapi.responses import StreamingResponse

@app.get("/ask/stream")
async def ask_stream(question: str):
    async def generate():
        async for chunk in rag_chain.astream(question):
            yield chunk
    return StreamingResponse(generate(), media_type="text/plain")
```

### Deployment Notes

- Replace local Chroma with persistent store (PGVector, Pinecone) for production.
- Add authentication and rate limiting for public APIs.
- Deploy to Render, Railway, Fly.io, or a VPS.
