# TurboQuant

**論文：** TurboQuant: Online Vector Quantization with Near-optimal Distortion Rate (Zandieh, Daliri, Hadian, Mirrokni, arXiv:2504.19874, 2025 年 4 月；在 ICLR 2026 發表）。

**相關工作：** PolarQuant（隨機預處理加極座標和純量量化，AISTATS 2026）；QJL，面向 KV Cache 的 1 位元量化 Johnson-Lindenstrauss 變換（arXiv:2406.03482）。

**作者部落格總結：** Google Research 部落格，2026 年 3 月 24 日。

![TurboQuant 流程總覽：旋轉、量化，再修正殘差](https://raw.githubusercontent.com/SAILTECHTEAM/knowledge-base/main/static/img/cv_img/TurboQuantimg/image1.png)

## 為什麼 KV Cache 需要壓縮

![KV Cache 記憶體隨上下文長度的增長](https://raw.githubusercontent.com/SAILTECHTEAM/knowledge-base/main/static/img/cv_img/TurboQuantimg/image2.png)

解碼器 Transformer 一次生成一個 token。每一步對全部過去 token 的注意力都要用到它們的鍵和值，重算一遍代價很高，所以模型把它們快取下來，這就是 KV Cache。

### KV Cache

![不用快取的重算注意力，與使用 KV Cache 的重用之對比](https://raw.githubusercontent.com/SAILTECHTEAM/knowledge-base/main/static/img/cv_img/TurboQuantimg/image3.png)

每生成一個新 token，注意力都要計算當前查詢與歷史 token 的鍵和值的互動。為了避免重複計算，過去 token 的鍵和值被存下來。當上下文達到幾十萬甚至上百萬 token 時，這個快取可能超過模型權重本身，成為 serving 時主要的記憶體瓶頸。

### 記憶體佔用舉例

![長上下文下 KV Cache 記憶體的例子](https://raw.githubusercontent.com/SAILTECHTEAM/knowledge-base/main/static/img/cv_img/TurboQuantimg/image4.png)

長上下文推理之所以貴，很大程度上是因為這個快取。粗略地說，大模型上的很長上下文只算快取就可能需要 TB 量級的 GPU 記憶體，批量大小和並發數都受它限制。

## TurboQuant 的核心思想

TurboQuant 是一種在線的、與資料無關的 KV Cache 量化方法。它保留完整的注意力結構，只壓縮鍵向量和值向量的存法。壓縮分兩個階段：

```text
第一階段，主量化：隨機旋轉加上接近最優的
  純量量化（即 PolarQuant 的做法）。
第二階段，殘差修正：對量化殘差做 1 位元量化 JL
  素描（QJL），用來恢復注意力內積的無偏估計。
```

第一階段最小化均方誤差。第二階段之所以必要，是因為均方誤差最優的量化器在內積上仍有偏差，而注意力依賴的正是內積。QJL 並不直接重建原向量，它用很低的代價修正估計，使查詢和鍵的內積估計保持接近無偏。

:::info[位元數從哪裡來]
2.5 位元、3.5 位元這類數字是平均值。少數離群通道用較高精度量化，其餘通道用較低精度量化。例如 32 個通道用 3 位元、96 個通道用 2 位元，平均就是每通道 2.5 位元。
:::

## 隨機旋轉

傳統純量量化最怕少數座標遠大於其餘座標。量化格子為了裝下離群值被拉得很大，小數值落進同一個格子就分不開了。

TurboQuant 在量化之前先做一次隨機正交旋轉。對兩邊施加同一個旋轉時，歐氏範數和內積都不變，注意力依賴的幾何關係也就不變。旋轉把離群座標的能量分散到很多維度，不再有單個座標一家獨大。

在高維旋轉之後，單個座標服從一個集中且解析形式已知的分佈，接近高斯分佈。對這個分佈配套的純量量化器（Lloyd-Max）接近最優，而且不需要每個資料塊各自的縮放和零點參數。省掉這些全精度存放的塊參數，是記憶體節省的主要來源之一，而傳統按塊量化必須存放它們。

## 主量化階段

![旋轉後座標的分組量化](https://raw.githubusercontent.com/SAILTECHTEAM/knowledge-base/main/static/img/cv_img/TurboQuantimg/image8.png)

![主量化階段的量化區間劃分](https://raw.githubusercontent.com/SAILTECHTEAM/knowledge-base/main/static/img/cv_img/TurboQuantimg/image9.png)

旋轉後的向量逐個座標用配套的純量碼本量化，一般在 3 到 4 位元。解量化把每個編號映射回對應的中心點，再做逆旋轉回到原空間。得到的向量在均方誤差下已經接近原始的鍵和值，但在很低的位寬下，剩下的誤差仍然足以擾動注意力內積，這就是下面殘差階段的由來。

![解量化回到原嵌入空間的路徑](https://raw.githubusercontent.com/SAILTECHTEAM/knowledge-base/main/static/img/cv_img/TurboQuantimg/image10.png)

注意力在原嵌入空間裡計算查詢和鍵的內積，解量化後的向量必須先回到這個空間才能參與注意力計算。只靠主階段的重建，在超低位寬下精度不夠，所以需要殘差階段補上。

## QJL 殘差修正階段

![對量化殘差做 QJL 素描以修正內積](https://raw.githubusercontent.com/SAILTECHTEAM/knowledge-base/main/static/img/cv_img/TurboQuantimg/image11.png)

殘差是原向量與主階段重建之差。QJL 用一個隨機矩陣投影殘差，只保留每個投影的符號，每個投影約花費 1 位元。查詢到來時，對查詢做同樣的投影，就可以估計缺掉的內積項。這個估計按構造是無偏的，所以儘管每次素描都很粗，注意力分數仍然圍繞真值波動。

:::caution[已發表質量結論的適用範圍]
論文報道在平均 3.5 位元下 LongBench 分數接近無損，在 2.5 位元下平均只有小幅下降，注意力 logit 計算最快約 8 倍（H100 上 4 位元鍵相對 32 位元基線）。這個加速針對的是注意力 logit，不是端到端推理。獨立復現發現在 3 位元下，推理和很長檢索任務上的下降更大。3 位元的設置應當按任務看待。
:::

## 實驗結果

在 LongBench 上，平均 3.5 位元的 TurboQuant 分數接近全量 16 位元快取（報道的平均分約 50.1），而 KIVI 之類的方法要用約 5 位元才達到類似質量。不帶 QJL 的 PolarQuant 變體下降明顯，說明在超低位寬下增益主要來自殘差修正。

| 設置 | 有效位元 | 報道的表現 |
| :--- | :--- | :--- |
| 全量快取 | 16 | 基準質量 |
| TurboQuant | 3.5 | 在 LongBench 上接近基準 |
| TurboQuant | 2.5 | 平均小幅下降 |
| KIVI | 5 | 用更高位寬達到類似質量 |
| 只有 PolarQuant | 低 | 不帶 QJL 時下降明顯 |
