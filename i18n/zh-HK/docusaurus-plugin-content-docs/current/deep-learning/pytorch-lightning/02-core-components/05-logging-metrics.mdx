# 日誌與指標 (Logging and Metrics)

Lightning 透過 `self.log()` 提供了一個統一的日誌記錄介面，它可以與多個後端整合。指標會自動在每個 step 追蹤並在每個 epoch 進行彙總。

## self.log 方法

```python
class MyModel(L.LightningModule):
    def training_step(self, batch, batch_idx):
        x, y = batch
        loss = self(x, y)
        
        # 基本日誌記錄
        self.log("train_loss", loss)
        
        return loss
```

### 日誌記錄參數

```python
def training_step(self, batch, batch_idx):
    x, y = batch
    loss = self(x, y)
    
    self.log(
        name="train_loss",     # 指標名稱
        value=loss,          # 指標值
        on_step=False,      # 是否在每個 step 記錄
        on_epoch=True,     # 是否在 epoch 結束時彙總
        prog_bar=False,    # 是否顯示在進度條上
        logger=True,      # 是否記錄到 logger
        reduce_fx=torch.mean  # 跨設備/epoch 歸約方式 (預設: mean)
    )
```

| 參數 | 描述 | 常見值 |
| :--- | :--- | :--- |
| `name` | 指標名稱 | `"train_loss"`, `"val_acc"` |
| `value` | 指標值 | Float tensor 或數字 |
| `on_step` | 每個 batch 記錄一次 | `True`/`False` |
| `on_epoch` | 在 epoch 結束時彙總 | `True` (預設) |
| `prog_bar` | 顯示在進度條上 | `True`/`False` |
| `logger` | 記錄到 logger | `True` (預設) |
| `reduce_fx` | 跨設備歸約方式 | `torch.mean` (預設) |

### Step 與 Epoch 日誌記錄

```python
def training_step(self, batch, batch_idx):
    loss = self.compute_loss(batch)
    
    # 記錄每個 step (詳細，適合偵錯)
    self.log("train_loss_step", loss, on_step=True, on_epoch=False)
    
    # 記錄 epoch 級別 (自動彙總)
    self.log("train_loss", loss, on_step=False, on_epoch=True)
    
    return loss
```

| 配置 | 行為 |
| :--- | --- |
| `on_step=True, on_epoch=False` | 記錄每個 batch |
| `on_step=False, on_epoch=True` | 記錄 epoch 平均值 |
| `on_step=True, on_epoch=True` | 同時記錄 step 和 epoch |

:::tip[進度條]
將 `prog_bar=True` 用於關鍵指標，以直觀地監控訓練。避免過度使用——指標太多會拖慢進度條。
:::

## log_dict

一次記錄多個指標：

```python
def validation_step(self, batch, batch_idx):
    x, y = batch
    preds = self(x)
    loss = F.cross_entropy(preds, y)
    
    preds_idx = torch.argmax(preds, dim=1)
    acc = (preds_idx == y).float().mean()
    
    # 多個指標
    self.log_dict({
        "val_loss": loss,
        "val_acc": acc,
    }, on_step=False, on_epoch=True)
    
    return loss
```

class MyLogger(Logger):
    @property
    def name(self):
        return "my_logger"
    
    @property
    def version(self):
        return "v1"
    
    def log_hyperparams(self, params):

## 指標整合

### 使用 TorchMetrics

Lightning 與 `torchmetrics` 整合以提供標準化的指標：

```python
import torchmetrics

class MyModel(L.LightningModule):
    def __init__(self):
        super().__init__()
        self.accuracy = torchmetrics.Accuracy(task="multiclass", num_classes=10)
        self.f1 = torchmetrics.F1Score(task="multiclass", num_classes=10)
    
    def validation_step(self, batch, batch_idx):
        x, y = batch
        preds = self.model(x)
        
        # 直接更新指標
        self.accuracy(preds, y)
        self.f1(preds, y)
        
        # 直接記錄指標物件
        self.log("val_acc", self.accuracy, on_epoch=True)
        self.log("val_f1", self.f1, on_epoch=True)
        
        return F.cross_entropy(preds, y)
```

:::tip[自動指標計算與重設]
當你直接使用 `self.log()` 記錄一個 `torchmetrics.Metric` 物件時，Lightning 會自動在 epoch 結束時呼叫 `.compute()`，並在下一個 epoch 開始時呼叫 `.reset()`。你不需要為此手動實作 `on_validation_epoch_end`。
:::

## 常見的日誌記錄模式

### 僅記錄損失

```python
def training_step(self, batch, batch_idx):
    loss = self.compute_loss(batch)
    
    self.log("train_loss", loss, on_step=True, on_epoch=True, prog_bar=True)
    
    return loss
```

### 記錄損失和準確率

```python
def validation_step(self, batch, batch_idx):
    x, y = batch
    preds = self(x)
    
    loss = F.cross_entropy(preds, y)
    preds_class = torch.argmax(preds, dim=1)
    acc = (preds_class == y).float().mean()
    
    self.log_dict({
        "val_loss": loss,
        "val_acc": acc,
    }, on_step=False, on_epoch=True, prog_bar=True)
    
    return loss
```

### 記錄自訂指標

```python
def training_step(self, batch, batch_idx):
    x, y = batch
    output = self(x)
    
    # 自訂指標：平均預測信賴度
    probs = F.softmax(output, dim=1)
    confidence = probs.max(dim=1)[0].mean()
    
    self.log("train_confidence", confidence, on_step=True)
    
    return F.cross_entropy(output, y)
```

## 在不同階段的日誌記錄

### 訓練 (Training)

```python
def training_step(self, batch, batch_idx):
    loss = self.compute_loss(batch)
    
    # Step 級別的日誌記錄
    self.log("train_loss", loss, on_step=True, on_epoch=True)
    
    return loss
```

### 驗證 (Validation)

```python
def validation_step(self, batch, batch_idx):
    loss = self.compute_loss(batch)
    self.log("val_loss", loss, on_step=False, on_epoch=True)
    
    return loss
```

### 測試 (Test)

```python
def test_step(self, batch, batch_idx):
    loss = self.compute_loss(batch)
    self.log("test_loss", loss, on_step=False, on_epoch=True)
    
    return loss
```

## 範例：完整的日誌記錄設定

```python
import lightning as L
import torch
import torchmetrics
import torch.nn.functional as F

class LitModel(L.LightningModule):
    def __init__(self, num_classes=10):
        super().__init__()
        self.model = torch.nn.Linear(784, num_classes)
        self.accuracy = torchmetrics.Accuracy(task="multiclass", num_classes=num_classes)
    
    def forward(self, x):
        return self.model(x.view(x.size(0), -1))
    
    def configure_optimizers(self):
        return torch.optim.Adam(self.parameters(), lr=1e-3)
    
    def training_step(self, batch, batch_idx):
        x, y = batch
        logits = self(x)
        loss = F.cross_entropy(logits, y)
        
        self.log(
            "train_loss", loss,
            on_step=True, on_epoch=True,
            prog_bar=True, logger=True
        )
        
        return loss
    
    def validation_step(self, batch, batch_idx):
        x, y = batch
        logits = self(x)
        loss = F.cross_entropy(logits, y)
        
        self.accuracy(logits, y)
        
        self.log_dict({
            "val_loss": loss,
            "val_acc": self.accuracy,
        }, on_step=False, on_epoch=True, prog_bar=True)
        
        return loss
```

## 比較：在原生 PyTorch 中的日誌記錄

| 方面 | 原生 PyTorch | Lightning |
| :--- | :--- | :--- |
| 日誌記錄 | 每個 step 手動處理 | `self.log()` |
| 彙總 (Aggregation) | 手動平均 | 自動處理 |
| 多個日誌記錄器 | 多個套件 | `logger=[...]` |
| 進度條 | 使用 `tqdm` 手動處理 | `prog_bar=True` |
| 指標重設 | 手動處理 | `on_epoch_end` 或自動 |

:::tip[一致的日誌記錄]
始終使用 `self.log()`。避免混合使用手動日誌記錄——這會破壞監控指標的檢查點回呼的整合。
:::
