# 終端機多工器

終端機多工器允許透過單一視窗管理多個終端機工作階段，支援在 SSH 連線中斷後分離和重新連線，並在斷網後保持程序運行。

---

## 比較

| 特性 | Zellij | tmux | dtach |
| :--- | :--- | :--- | :--- |
| **語言** | Rust | C | C |
| **設定方式** | KDL（人類可讀格式） | tmux.conf（DSL） | 最少的命令列參數 |
| **版面配置系統** | 內建浮動/堆疊窗格 | 手動分割管理 | 不支援版面配置管理 |
| **工作階段管理** | 完整（列出/連線/終止） | 完整（列出/連線/終止） | 無（僅支援單一程序） |
| **外掛系統** | 基於 WASM 的外掛 | 基於指令碼的擴充 | 無 |
| **學習曲線** | 低（介面直覺） | 中等（設定複雜） | 非常低 |
| **預設狀態列** | 有（資訊豐富） | 有（可自訂） | 無 |
| **多工功能** | 完整（窗格、分頁、版面配置） | 完整（窗格、視窗） | 無（僅支援單一程序） |
| **開發狀態** | 活躍 | 活躍 | 維護模式 |
| **執行檔大小** | ~15 MB | ~4 MB | ~30 KB |

### 適用場景

- **Zellij** — 建議用於新專案。直覺的按鍵綁定、內建版面配置管理和 WASM 外掛支援使其成為現代工作流程的最佳選擇。
- **tmux** — 成熟的標準工具，生態系龐大。當團隊已使用 tmux 或現有設定/指令碼依賴 tmux 時，優先選擇。
- **dtach** — 最小化的程序分離/重連工具，無多工功能。當只需要在登出後保持單一程序運行（如長時間執行的建置或開發伺服器），且不需要窗格管理或工作階段切換時使用。

## Zellij

Zellij 是一個用 Rust 編寫的現代終端機多工器，注重人體工學和易用性。其預設按鍵綁定可透過浮動說明窗格發現。

### 主要功能

- **工作階段管理** — 建立、連線、分離和終止工作階段
- **版面配置** — 將複雜的窗格排列儲存為命名版面配置並還原
- **浮動窗格** — 在平鋪版面配置上疊加浮動窗格
- **堆疊窗格** — 將窗格堆疊在單一區域以便快速切換
- **WASM 外掛** — 透過 WebAssembly 外掛擴充功能

### 快速開始

```bash
# 啟動一個新的命名工作階段
zellij --session myproject

# 連線到現有工作階段
zellij attach myproject

# 列出活躍工作階段
zellij list-sessions
```

### 預設按鍵綁定

| 按鍵 | 操作 |
| :--- | :--- |
| `Ctrl+t` | 前綴鍵（所有按鍵綁定以此開頭） |
| `Ctrl+t` 然後 `n` | 新增窗格 |
| `Ctrl+t` 然後 `←/→/↑/↓` | 在窗格間切換 |
| `Ctrl+t` 然後 `d` | 分離工作階段 |
| `Ctrl+t` 然後 `x` | 關閉窗格 |
| `Ctrl+t` 然後 `?` | 切換浮動說明窗格 |

### CLI 用法

Zellij 可完全透過命令列與 shell 腳本驅動，包括控制主機上其他位置執行的工作階段。這是無頭工作流、CI 流水線與工作區自動化的基礎。

每個窗格透過 `$ZELLIJ_PANE_ID` 環境變數暴露其 ID。多數操作接受 `--pane-id`（如 `terminal_3`）或 `--tab-id` 來定向特定元素而無需切換焦點。

#### 命令參考

| 命令 | 用途 |
| :--- | :--- |
| `zellij attach --create-background NAME` | 建立無頭工作階段且不附加 |
| `zellij --session NAME action <subcommand>` | 向主機上任意工作階段發送操作 |
| `zellij action list-panes --json` | 列出窗格的 ID、標題及元資料 |
| `zellij action new-pane [--name N] -- <cmd>` | 開啟執行命令的窗格；輸出其窗格 ID |
| `zellij action send-keys --pane-id N "Enter" "ctrl c"` | 向窗格發送按鍵 |
| `zellij action paste --pane-id N "text"` | 透過 bracketed paste 貼上文字（多行更可靠） |
| `zellij action dump-screen --pane-id N --full` | 擷取窗格的可視區與回捲歷史 |
| `zellij subscribe --pane-id N --format json` | 即時串流輸出窗格內容 |

:::tip[優先使用 paste 而非輸入]
`action paste` 透過 bracketed-paste 模式寫入文字，向窗格注入命令時比 `send-keys` 更可靠。隨後用 `send-keys "Enter"` 執行。
:::

#### 在窗格中執行命令

`zellij action new-pane`（等價於頂層命令 `zellij run`）在新窗格中啟動命令並輸出新窗格 ID，腳本可捕獲它以串聯後續操作：

```bash
# 開啟窗格，捕獲其 ID，並在其中啟動建置
PANE_ID=$(zellij action new-pane --name "build")
zellij action paste --pane-id "$PANE_ID" "cargo build 2>&1" &&
zellij action send-keys --pane-id "$PANE_ID" "Enter"
```

阻塞旗標會暫停呼叫 shell 直到窗格中的命令結束，從而支援帶手動重試的循序化腳本流水線：

```bash
# 重試直到測試通過，再建置
zellij action new-pane --block-until-exit-success --name "tests" -- cargo test
zellij action new-pane --block-until-exit-success --name "release" -- cargo build --release
```

#### 控制背景工作階段

背景工作階段以分離方式建立，完全透過全域 `--session` 旗標從 CLI 驅動——適合 CI 或遠端自動化：

```bash
#!/usr/bin/env bash
set -euo pipefail

# 以緊湊布局啟動無頭工作階段
zellij attach --create-background ci-runner options --default-layout compact

# 在該工作階段中開啟窗格並執行建置
BUILD_PANE=$(zellij --session ci-runner action new-pane --name "build")
zellij --session ci-runner action paste --pane-id "$BUILD_PANE" "cargo build 2>&1" &&
zellij --session ci-runner action send-keys --pane-id "$BUILD_PANE" "Enter"

# 串流輸出建置內容並篩選相關行
zellij --session ci-runner subscribe --pane-id "$BUILD_PANE" --format json \
  | jq --unbuffered 'select(.event == "pane_update") | .viewport[] | select(test("error|warning|Finished"))'
```

:::note[唯讀存取]
`zellij watch NAME` 以唯讀模式附加到工作階段——可見輸出但不接受任何輸入，適合共享觀察。
:::

#### 實際應用示例

以上模式可組合成可重用的工作區腳本。

**深度學習訓練工作區**

一個分離式、可重用的工作階段，包含訓練、GPU 監控、日誌查看和 TensorBoard 的獨立窗格。可重複呼叫：

```bash
#!/usr/bin/env bash
# ~/.local/bin/dl-train-startup — start or reattach to the training workspace
set -euo pipefail
SESSION="dl-train"

# Create the session in the background only if it doesn't already exist
if ! zellij list-sessions 2>/dev/null | grep -q "$SESSION"; then
  zellij attach --create-background "$SESSION"

  # Pane — training run, output tee'd to a log file for inspection
  zellij --session "$SESSION" action new-pane -- \
    bash -c "exec python -m my_project.train --config configs/resnet50.yaml 2>&1 | tee train.log"

  # Pane — live GPU utilization
  zellij --session "$SESSION" action new-pane -- watch -n 1 nvidia-smi

  # Pane — tail the training log
  zellij --session "$SESSION" action new-pane -- \
    bash -c "touch train.log; tail -F train.log"

  # Pane — TensorBoard, accessible from your browser
  zellij --session "$SESSION" action new-pane -- \
    bash -c "mkdir -p runs && tensorboard --logdir=runs --port=6006 --bind=0.0.0.0"
fi

zellij attach "$SESSION"
```

訓練在背景窗格持續執行，即使分離或斷開 SSH 連線也不會中斷。

### 安裝

最新的安裝選項請參閱官方說明：https://zellij.dev/documentation/installation.html

#### 透過 Cargo

編譯最新發行版（需要 Rust 工具鏈）：

```bash
cargo install --locked zellij
```

若透過 rustup 安裝 Cargo 後出現錯誤，先執行 `rustup update`。

#### 透過 cargo-binstall

跳過編譯，直接安裝預編譯二進位檔：

```bash
cargo binstall zellij
```

#### 透過預編譯二進位檔

從[發行頁面](https://github.com/zellij-org/zellij/releases)下載對應平台的壓縮檔，解壓並執行二進位檔：

```bash
tar -xvf zellij*.tar.gz
chmod +x zellij
./zellij
```

將二進位檔移動到 `$PATH` 中的目錄，即可在任意位置執行。

#### 透過套件管理員

Zellij 已打包到多個第三方儲存庫，套件狀態見 [Repology](https://repology.org/project/zellij/versions)：

```bash
# macOS
brew install zellij

# Arch Linux
pacman -S zellij
```

## tmux

tmux 是最廣泛採用的終端機多工器，自 2007 年以來持續發展。它使用自訂設定 DSL，支援透過 shell 指令碼進行廣泛的腳本化操作。

### 主要功能

- **工作階段管理** — 連線、分離和切換工作階段
- **視窗和窗格** — 將終端機分割為多個窗格和視窗
- **腳本化** — 完整的命令列介面用於自動化
- **狀態列** — 高度可自訂的狀態行
- **剪貼簿整合** — 支援系統剪貼簿的複製模式

### 快速開始

```bash
# 啟動新工作階段
tmux new -s myproject

# 連線到現有工作階段
tmux attach -t myproject

# 列出工作階段
tmux list-sessions
```

### 預設按鍵綁定

| 按鍵 | 操作 |
| :--- | :--- |
| `Ctrl+b` | 前綴鍵 |
| `Ctrl+b` 然後 `c` | 新增視窗 |
| `Ctrl+b` 然後 `%` | 垂直分割 |
| `Ctrl+b` 然後 `"` | 水平分割 |
| `Ctrl+b` 然後方向鍵 | 在窗格間切換 |
| `Ctrl+b` 然後 `d` | 分離工作階段 |

### CLI 用法

tmux 透過命令列介面暴露其全部功能，因此工作階段、視窗和窗格均可由 shell 腳本建立和控制——包括在不附加的情況下向執行中的工作階段注入命令。這使 tmux 適用於引導腳本、遠端編排和可重現的開發環境。

#### 命令參考

| 命令 | 用途 |
| :--- | :--- |
| `tmux new-session -d -s NAME` | 建立分離工作階段（不附加） |
| `tmux has-session -t NAME` | 工作階段存在時離開碼為 0（腳本守衛） |
| `tmux send-keys -t TARGET 'cmd' C-m` | 向窗格發送命令並換行 |
| `tmux new-window -t NAME -n win` | 建立視窗 |
| `tmux split-window -v -t TARGET` | 分割活動窗格（`-v` 上下堆疊，`-h` 左右並排） |
| `tmux capture-pane -p -t TARGET` | 將窗格可見內容輸出到 stdout |
| `tmux list-sessions`（`tmux ls`） | 列出工作階段 |
| `tmux kill-session -t NAME` | 終止工作階段 |
| `tmux source-file ~/.tmux.conf` | 重新載入設定 |

目標以 `session`、`session:window` 或 `session:window.pane` 的形式解析。為保證腳本可靠性，優先使用最具體的目標（如 `dev:0.1`），或捕獲 `new-session` 回傳的窗格 ID。

:::caution[避免 send-keys 競態]
`tmux new-session -d` 在新窗格的 shell 準備好讀取輸入之前就回傳，因此緊隨其後的 `send-keys` 可能被回顯而非執行。要麼直接把命令傳給 `new-session`，要麼加一個短暫延遲：

```bash
tmux new-session -d -s dev 'cd ~/projects/myapp && exec bash'   # 命令在窗格的 shell 內執行
# 或
tmux new-session -d -s dev && sleep 0.5
```

:::

#### 腳本化工作區搭建

常見模式是編寫冪等的啟動腳本：若工作階段已存在則重用，否則分離式建置全新的多窗格布局，最後再附加：

```bash
#!/usr/bin/env bash
set -euo pipefail
SESSION="dev"

# 若工作階段已存在則重用
if tmux has-session -t "$SESSION" 2>/dev/null; then
  exec tmux attach -t "$SESSION"
fi

# 分離式建置布局
tmux new-session -d -s "$SESSION" -n editor
tmux send-keys -t "$SESSION:editor" 'cd ~/projects/myapp && vim .' C-m
tmux split-window -v -p 30 -t "$SESSION:editor"
tmux send-keys -t "$SESSION:editor.1" 'cd ~/projects/myapp' C-m

tmux new-window -t "$SESSION" -n server
tmux send-keys -t "$SESSION:server" 'cd ~/projects/myapp && npm run dev' C-m

tmux new-window -t "$SESSION" -n logs
tmux send-keys -t "$SESSION:logs" 'tail -f ~/projects/myapp/logs/dev.log' C-m

tmux select-window -t "$SESSION:editor"
tmux attach -t "$SESSION"
```

#### 遠端控制

由於每條 `tmux <command>` 都透過 socket 與伺服器通訊，執行中的工作階段可從任意位置驅動——包括透過 SSH——而無需附加：

```bash
# 在遠端主機的分離工作階段中重啟服務
ssh user@host "tmux send-keys -t api 'sudo systemctl restart api' C-m"

# 遠端查看窗格輸出
ssh user@host "tmux capture-pane -p -t api:0.0" | tail -n 20
```

#### 實際應用示例

以上模式可組合成可重用的工作區腳本。

**深度學習訓練工作區**

一個分離式、可重用的工作階段，包含訓練 + GPU/日誌監控視窗，以及 TensorBoard。可重複呼叫：

```bash
#!/usr/bin/env bash
# ~/.local/bin/dl-train-startup — start or reattach to the training workspace
set -euo pipefail
SESSION="dl-train"

# Reuse the existing session if present
if tmux has-session -t "$SESSION" 2>/dev/null; then
  exec tmux attach -t "$SESSION"
fi

# Window "train": training top-left, GPU monitor right, log tail bottom-left
tmux new-session -d -s "$SESSION" -n train \
  "python -m my_project.train --config configs/resnet50.yaml 2>&1 | tee train.log"
tmux split-window -h -t "$SESSION:train" "watch -n 1 nvidia-smi"
tmux split-window -v -t "$SESSION:train.0" "tail -F train.log"

# Window "tensorboard": single pane
tmux new-window -t "$SESSION" -n tensorboard \
  "mkdir -p runs && tensorboard --logdir=runs --port=6006 --bind=0.0.0.0"

tmux select-window -t "$SESSION:train"
tmux attach -t "$SESSION"
```

訓練在背景窗格持續執行，即使分離或斷開 SSH 連線也不會中斷。

## dtach

dtach 是一個極簡程式，模擬 tmux 或 screen 的分離功能。它包裝單個程序，允許分離和重新連線，無工作階段管理或多工開銷。

### 主要功能

- **程序連線/分離** — 連線和分離單個執行中的程序
- **最小體積** — ~30 KB 執行檔，無設定檔
- **零相依** — 純 C 編寫，無外部函式庫
- **快速啟動** — 幾乎即時的 Socket 建立

### 快速開始

```bash
# 啟動一個 shell socket
dtach -A /tmp/my_socket

# 啟動一個執行特定指令的 socket
dtach -A /tmp/build_socket make build

# 重新連線到現有 socket
dtach -a /tmp/my_socket
```

### 命令參數

| 參數 | 說明 |
| :--- | :--- |
| `-A` | 建立或連線到 Socket |
| `-a` | 連線到現有 Socket（不存在則失敗） |
| `-c` | 建立新 Socket（不連線） |
| `-z` | 抑制建立訊息 |
| `-r` | 以唯讀模式連線 |
| `-e` | 指定跳脫字元（預設：`^\\`） |

### 安裝

```bash
# Ubuntu/Debian
sudo apt install dtach

# Arch Linux
pacman -S dtach

# macOS
brew install dtach

# 從原始碼編譯
git clone https://github.com/crigertyp/dtach.git
cd dtach
./configure && make && sudo make install
```
