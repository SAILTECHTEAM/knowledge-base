# 终端复用器

终端复用器允许通过单个窗口管理多个终端会话，支持在 SSH 连接中断后分离和重新连接，并在断网后保持进程运行。

---

## 对比

| 特性 | Zellij | tmux | dtach |
| :--- | :--- | :--- | :--- |
| **语言** | Rust | C | C |
| **配置方式** | KDL（人类可读格式） | tmux.conf（DSL） | 最少的命令行参数 |
| **布局系统** | 内置浮动/堆叠面板 | 手动分割管理 | 不支持布局管理 |
| **会话管理** | 完整（列出/附加/终止） | 完整（列出/附加/终止） | 无（仅支持单一进程） |
| **插件系统** | 基于 WASM 的插件 | 基于脚本的扩展 | 无 |
| **学习曲线** | 低（界面直观） | 中等（配置复杂） | 非常低 |
| **默认状态栏** | 有（信息丰富） | 有（可自定义） | 无 |
| **多路复用** | 完整（面板、标签页、布局） | 完整（面板、窗口） | 无（仅支持单一进程） |
| **开发状态** | 活跃 | 活跃 | 维护模式 |
| **二进制大小** | ~15 MB | ~4 MB | ~30 KB |

### 适用场景

- **Zellij** — 推荐用于新项目。直观的键绑定、内置布局管理和 WASM 插件支持使其成为现代工作流程的最佳选择。
- **tmux** — 成熟的标准工具，生态庞大。当团队已使用 tmux 或现有配置/脚本依赖 tmux 时，优先选择。
- **dtach** — 最小化的进程分离/重连工具，无多路复用功能。当只需要在登出后保持单个进程运行（如长时间运行的构建或开发服务器），且不需要面板管理或会话切换时使用。

## Zellij

Zellij 是一个用 Rust 编写的现代终端复用器，注重人体工程学和易用性。其默认键绑定可通过浮动帮助面板发现。

### 主要特性

- **会话管理** — 创建、附加、分离和终止会话
- **布局管理** — 将复杂的面板排列保存为命名布局并恢复
- **浮动面板** — 在平铺布局上叠加浮动面板
- **堆叠面板** — 将面板堆叠在单个区域以便快速切换
- **WASM 插件** — 通过 WebAssembly 插件扩展功能

### 快速开始

```bash
# 启动一个新的命名会话
zellij --session myproject

# 附加到现有会话
zellij attach myproject

# 列出活跃会话
zellij list-sessions
```

### 默认键绑定

| 按键 | 操作 |
| :--- | :--- |
| `Ctrl+t` | 前缀键（所有键绑定以此开头） |
| `Ctrl+t` 然后 `n` | 新建面板 |
| `Ctrl+t` 然后 `←/→/↑/↓` | 在面板间切换 |
| `Ctrl+t` 然后 `d` | 分离会话 |
| `Ctrl+t` 然后 `x` | 关闭面板 |
| `Ctrl+t` 然后 `?` | 切换浮动帮助面板 |

### CLI 用法

Zellij 可完全通过命令行和 shell 脚本驱动，包括控制主机上其他位置运行的会话。这是无头工作流、CI 流水线和工作区自动化的基础。

每个面板通过 `$ZELLIJ_PANE_ID` 环境变量暴露其 ID。多数操作接受 `--pane-id`（如 `terminal_3`）或 `--tab-id` 来定向特定元素而无需切换焦点。

#### 命令参考

| 命令 | 用途 |
| :--- | :--- |
| `zellij attach --create-background NAME` | 创建无头会话且不附加 |
| `zellij --session NAME action <subcommand>` | 向主机上任意会话发送操作 |
| `zellij action list-panes --json` | 列出面板的 ID、标题及元数据 |
| `zellij action new-pane [--name N] -- <cmd>` | 打开运行命令的面板；输出其面板 ID |
| `zellij action send-keys --pane-id N "Enter" "ctrl c"` | 向面板发送按键 |
| `zellij action paste --pane-id N "text"` | 通过 bracketed paste 粘贴文本（多行更可靠） |
| `zellij action dump-screen --pane-id N --full` | 捕获面板的可视区与回滚历史 |
| `zellij subscribe --pane-id N --format json` | 实时流式输出面板内容 |

:::tip[优先使用 paste 而非输入]
`action paste` 通过 bracketed-paste 模式写入文本，向面板注入命令时比 `send-keys` 更可靠。随后用 `send-keys "Enter"` 执行。
:::

#### 在面板中运行命令

`zellij action new-pane`（等价于顶层命令 `zellij run`）在新面板中启动命令并输出新面板 ID，脚本可捕获它以串联后续操作：

```bash
# 打开面板，捕获其 ID，并在其中启动构建
PANE_ID=$(zellij action new-pane --name "build")
zellij action paste --pane-id "$PANE_ID" "cargo build 2>&1" &&
zellij action send-keys --pane-id "$PANE_ID" "Enter"
```

阻塞标志会暂停调用 shell 直到面板中的命令结束，从而支持带手动重试的顺序化脚本流水线：

```bash
# 重试直到测试通过，再构建
zellij action new-pane --block-until-exit-success --name "tests" -- cargo test
zellij action new-pane --block-until-exit-success --name "release" -- cargo build --release
```

#### 控制后台会话

后台会话以分离方式创建，完全通过全局 `--session` 标志从 CLI 驱动——适合 CI 或远程自动化：

```bash
#!/usr/bin/env bash
set -euo pipefail

# 以紧凑布局启动无头会话
zellij attach --create-background ci-runner options --default-layout compact

# 在该会话中打开面板并运行构建
BUILD_PANE=$(zellij --session ci-runner action new-pane --name "build")
zellij --session ci-runner action paste --pane-id "$BUILD_PANE" "cargo build 2>&1" &&
zellij --session ci-runner action send-keys --pane-id "$BUILD_PANE" "Enter"

# 流式输出构建内容并筛选相关行
zellij --session ci-runner subscribe --pane-id "$BUILD_PANE" --format json \
  | jq --unbuffered 'select(.event == "pane_update") | .viewport[] | select(test("error|warning|Finished"))'
```

:::note[只读访问]
`zellij watch NAME` 以只读模式附加到会话——可见输出但不接受任何输入，适合共享观察。
:::

### 安装

最新的安装选项请参阅官方说明：https://zellij.dev/documentation/installation.html

#### 通过 Cargo

编译最新发布版（需要 Rust 工具链）：

```bash
cargo install --locked zellij
```

若通过 rustup 安装 Cargo 后出现错误，先运行 `rustup update`。

#### 通过 cargo-binstall

跳过编译，直接安装预编译二进制：

```bash
cargo binstall zellij
```

#### 通过预编译二进制

从[发布页面](https://github.com/zellij-org/zellij/releases)下载对应平台的压缩包，解压并运行二进制：

```bash
tar -xvf zellij*.tar.gz
chmod +x zellij
./zellij
```

将二进制移动到 `$PATH` 中的目录，即可在任意位置运行。

#### 通过包管理器

Zellij 已打包到多个第三方仓库，包状态见 [Repology](https://repology.org/project/zellij/versions)：

```bash
# macOS
brew install zellij

# Arch Linux
pacman -S zellij
```

## tmux

tmux 是最广泛采用的终端复用器，自 2007 年以来持续发展。它使用自定义配置 DSL，支持通过 shell 命令进行广泛的脚本化操作。

### 主要特性

- **会话管理** — 附加、分离和切换会话
- **窗口和面板** — 将终端分割为多个面板和窗口
- **脚本化** — 完整的命令行接口用于自动化
- **状态栏** — 高度可自定义的状态行
- **剪贴板集成** — 支持系统剪贴板的复制模式

### 快速开始

```bash
# 启动新会话
tmux new -s myproject

# 附加到现有会话
tmux attach -t myproject

# 列出会话
tmux list-sessions
```

### 默认键绑定

| 按键 | 操作 |
| :--- | :--- |
| `Ctrl+b` | 前缀键 |
| `Ctrl+b` 然后 `c` | 新建窗口 |
| `Ctrl+b` 然后 `%` | 垂直分割 |
| `Ctrl+b` 然后 `"` | 水平分割 |
| `Ctrl+b` 然后方向键 | 在面板间切换 |
| `Ctrl+b` 然后 `d` | 分离会话 |

### CLI 用法

tmux 通过命令行接口暴露其全部功能，因此会话、窗口和面板均可由 shell 脚本创建和控制——包括在不附加的情况下向运行中的会话注入命令。这使 tmux 适用于引导脚本、远程编排和可复现的开发环境。

#### 命令参考

| 命令 | 用途 |
| :--- | :--- |
| `tmux new-session -d -s NAME` | 创建分离会话（不附加） |
| `tmux has-session -t NAME` | 会话存在时退出码为 0（脚本守卫） |
| `tmux send-keys -t TARGET 'cmd' C-m` | 向面板发送命令并回车 |
| `tmux new-window -t NAME -n win` | 创建窗口 |
| `tmux split-window -v -t TARGET` | 分割活动面板（`-v` 上下堆叠，`-h` 左右并排） |
| `tmux capture-pane -p -t TARGET` | 将面板可见内容输出到 stdout |
| `tmux list-sessions`（`tmux ls`） | 列出会话 |
| `tmux kill-session -t NAME` | 终止会话 |
| `tmux source-file ~/.tmux.conf` | 重新加载配置 |

目标以 `session`、`session:window` 或 `session:window.pane` 的形式解析。为保证脚本可靠性，优先使用最具体的目标（如 `dev:0.1`），或捕获 `new-session` 返回的面板 ID。

:::caution[避免 send-keys 竞态]
`tmux new-session -d` 在新面板的 shell 准备好读取输入之前就返回，因此紧随其后的 `send-keys` 可能被回显而非执行。要么直接把命令传给 `new-session`，要么加一个短暂延迟：

```bash
tmux new-session -d -s dev 'cd ~/projects/myapp && exec bash'   # 命令在面板的 shell 内运行
# 或
tmux new-session -d -s dev && sleep 0.5
```

:::

#### 脚本化工作区搭建

常见模式是编写幂等的启动脚本：若会话已存在则复用，否则分离式构建全新的多面板布局，最后再附加：

```bash
#!/usr/bin/env bash
set -euo pipefail
SESSION="dev"

# 若会话已存在则复用
if tmux has-session -t "$SESSION" 2>/dev/null; then
  exec tmux attach -t "$SESSION"
fi

# 分离式构建布局
tmux new-session -d -s "$SESSION" -n editor
tmux send-keys -t "$SESSION:editor" 'cd ~/projects/myapp && vim .' C-m
tmux split-window -v -p 30 -t "$SESSION:editor"
tmux send-keys -t "$SESSION:editor.1" 'cd ~/projects/myapp' C-m

tmux new-window -t "$SESSION" -n server
tmux send-keys -t "$SESSION:server" 'cd ~/projects/myapp && npm run dev' C-m

tmux new-window -t "$SESSION" -n logs
tmux send-keys -t "$SESSION:logs" 'tail -f ~/projects/myapp/logs/dev.log' C-m

tmux select-window -t "$SESSION:editor"
tmux attach -t "$SESSION"
```

#### 远程控制

由于每条 `tmux <command>` 都通过 socket 与服务端通信，运行中的会话可从任意位置驱动——包括通过 SSH——而无需附加：

```bash
# 在远程主机的分离会话中重启服务
ssh user@host "tmux send-keys -t api 'sudo systemctl restart api' C-m"

# 远程查看面板输出
ssh user@host "tmux capture-pane -p -t api:0.0" | tail -n 20
```

### 安装

```bash
# macOS
brew install tmux

# Ubuntu/Debian
sudo apt install tmux

# Arch Linux
pacman -S tmux

# 从源码编译
git clone https://github.com/tmux/tmux.git
cd tmux
sh autogen.sh
./configure && make && sudo make install
```

## dtach

dtach 是一个极简程序，模拟 tmux 或 screen 的分离功能。它包装单个进程，允许分离和重新连接，无会话管理或多路复用开销。

### 主要特性

- **进程附加/分离** — 附加和分离单个运行中的进程
- **最小体积** — ~30 KB 二进制文件，无配置文件
- **零依赖** — 纯 C 编写，无外部库
- **快速启动** — 近乎即时的套接字创建

### 快速开始

```bash
# 启动一个 shell 套接字
dtach -A /tmp/my_socket

# 启动一个运行特定命令的套接字
dtach -A /tmp/build_socket make build

# 重新连接到现有套接字
dtach -a /tmp/my_socket
```

### 命令参数

| 参数 | 说明 |
| :--- | :--- |
| `-A` | 创建或附加到套接字 |
| `-a` | 附加到现有套接字（不存在则失败） |
| `-c` | 创建新套接字（不附加） |
| `-z` | 抑制创建消息 |
| `-r` | 以只读模式附加 |
| `-e` | 指定转义字符（默认：`^\\`） |

### 安装

```bash
# Ubuntu/Debian
sudo apt install dtach

# Arch Linux
pacman -S dtach

# macOS
brew install dtach

# 从源码编译
git clone https://github.com/crigertyp/dtach.git
cd dtach
./configure && make && sudo make install
```
